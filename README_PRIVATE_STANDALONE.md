# منصة المدارس الأهلية والخاصة — مشروع مستقل

هذه الحزمة لا تعتمد على مستودع أو Supabase مدارس التعليم العام.

## الحالة الحالية
- واجهة مدير النظام مخصصة للمدارس الأهلية والخاصة فقط.
- نظام «المدارس المستقلة/اشتراكات المعلمين» القديم أزيل من مسار التشغيل.
- جميع بيانات اتصال Supabase السابق أزيلت واستبدلت بقيم Placeholder.
- `supabase/migrations` يحتوي نواة قاعدة بيانات جديدة وفارغة للمدارس الخاصة.
- لا توجد أي بيانات مدارس أو مستخدمين من التعليم العام داخل الحزمة.


## ربط Supabase الجديد
1. أنشئ مشروع Supabase جديدًا وفارغًا.
2. ضع Project Ref وPublishable Key الجديدين في `standalone-private-config.js`.
3. أضف GitHub Secrets المذكورة في `.env.example`.
4. شغّل Workflow `Deploy Standalone Private Supabase`.
5. أنشئ أول مستخدم Auth لمدير النظام ثم أضف UUID الخاص به إلى `system_admins`.
6. أنشئ bucket باسم `private-school-files` واضبط سياسات التخزين قبل التشغيل الإنتاجي.

## قاعدة العزل
لا تستخدم أي URL أو Key أو Function من مشروع مدارس التعليم العام. أي تكامل مستقبلي بين النظامين يكون عبر بوابة خارجية مستقلة، وليس عبر مشاركة ملفات التشغيل أو قاعدة البيانات.

## فصل وظائف Supabase
`supabase/functions/` يحتوي فقط الوظائف التي تم تنظيفها لتناسب المشروع المستقل الجديد حاليًا:
- `system-admin`
- `private-school-provisioning`
- `private-school-session`

أما وظائف المنصة السابقة التي نحتاج الاستفادة من منطقها لاحقًا فقد نُقلت إلى `supabase/reference-functions/` ولا يقوم Workflow بنشرها. الهدف هو منع نشر وظيفة تعتمد على جداول أو بيانات المشروع السابق بالخطأ. يتم نقل كل وظيفة من reference إلى functions فقط بعد مراجعة عقد الجداول والصلاحيات الخاص بالمشروع الجديد.
